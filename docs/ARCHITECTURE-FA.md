# معماری فنی CASH KIOSK 2.3

## اجزا
- `src/cash-kiosk.js`: رابط کیوسک، دریافت درخواست‌های امروز از سامان، بررسی رمز، تشخیص نتیجه پرداخت، دریافت گردش صندوق و چاپ رسید.
- `src/main.js`: پردازش اصلی Electron؛ کنترل پنجره، چاپ PDF، خواندن توکن، هویت دستگاه، IPC محدود و اجرای سرور در نقش مدیر.
- `src/preload.js`: سطح API محدود بین صفحه سامانه و پردازش اصلی؛ هیچ توکنی به renderer داده نمی‌شود. رویدادهای ورودی NumPad از همین پل محدود عبور می‌کنند.
- `src/raw-numpad-helper.ps1`: شنونده Windows Raw Input در فرایند PowerShell مخفی؛ مسیر دستگاه را با شناسه Genius تطبیق می‌دهد و فقط ارقام و چهار کلید عملیاتی NumPad آن را به stdout ساخت‌یافته می‌فرستد.
- `src/coordination-server.js`: API داخلی روی TCP/5005؛ قفل اتمیک، وضعیت halted، آزادسازی اپراتوری و گزارش حسابرسی.
- `scripts/configure-device.ps1`: پیکربندی یک‌باره نقش دستگاه و توکن مشترک با ACL محدود.

## جریان پرداخت
1. کاربر رمز شش رقمی را وارد می‌کند.
2. کیوسک از سرور مرکزی قفل می‌گیرد.
3. اگر قفل موجود باشد، پرداخت متوقف می‌شود.
4. بعد از اخذ قفل، فهرست درخواست‌ها مجدداً از سامان دریافت می‌شود؛ فهرست قبلی برای تصمیم پرداخت استفاده نمی‌شود.
5. فقط پاسخ صریح رمز اشتباه اجازه رفتن به درخواست بعدی را می‌دهد.
6. پاسخ مبهم پرداخت، کیوسک را متوقف می‌کند و قفل مرکزی را به حالت halted می‌برد.
7. پاسخ قطعی موفق، شناسه درخواست را در همان اجرا مسدود می‌کند و قفل را با outcome=payment-success آزاد می‌کند.
8. خطای آزادسازی پس از پرداخت موفق، هرگز باعث تکرار درخواست پرداخت نمی‌شود؛ قفل برای بررسی دستی باقی می‌ماند.
9. چاپ رسید در پس‌زمینه انجام می‌شود و شکست چاپ هیچ اثری بر وضعیت پرداخت ندارد.

## ورودی اختصاصی NumPad
- در ویندوز، `main.js` اسکریپت کمکی PowerShell را اجرا می‌کند. اسکریپت با Win32 Raw Input و پنجره پیام مخفی، رویدادهای صفحه‌کلید را دریافت می‌کند.
- مسیر دستگاه باید شامل `VID_248A&PID_8367` باشد؛ سایر دستگاه‌ها برای ورود رمز پذیرفته نمی‌شوند.
- شناسه‌های مجازی `VK_NUMPAD0` تا `VK_NUMPAD9` (۹۶ تا ۱۰۵) به رقم تبدیل می‌شوند؛ `VK_DIVIDE`، `VK_SUBTRACT`، `VK_ADD` و `VK_MULTIPLY` به‌ترتیب به `/`، `-`، `+` و `*` تبدیل می‌شوند. فقط `keydown` ورودی می‌فرستد؛ `keyup` برای آزادسازی کلید و جلوگیری از تکرار نگه‌داری می‌شود.
- فرایند اصلی رویداد را بدون شرط فوکوس پنجره به renderer می‌فرستد؛ صفحه کیوسک باید بارگذاری شده و renderer آماده دریافت باشد.
- در دستگاه با نقش `client`، `before-input-event` ارقام legacy تمام کیبوردها را در پنجره کیوسک مسدود می‌کند؛ در سایر نقش‌ها این محدودیت با شناسایی دانگل فعال می‌شود. کادر رمز نیز `readonly` است؛ مقدار آن فقط با تابع داخلی `addDigit` تغییر می‌کند.
- ارقام در کادر به‌صورت متن واقعی نمایش داده می‌شوند و CSS پوشاننده رمز حذف شده است.
- با جداشدن دانگل، برنامه وضعیت دستگاه را به‌روز می‌کند. دستگاه `client` در نبود دانگل fail-closed است و کیبورد اصلی را جایگزین نمی‌کند؛ سایر نقش‌ها ورودی عادی کیبورد را حفظ می‌کنند.
- این طراحی جلوی ورود NumPad به برنامه‌های دیگر را وقتی آن برنامه‌ها در پیش‌زمینه‌اند نمی‌گیرد؛ مسدودسازی سراسری ورودی دستگاه در محدوده این نسخه نیست.

## رفتار رابط هنگام قفل قدیمی
- هشدار قفل قدیمی پس از ۱۰ ثانیه از رابط پاک می‌شود و کادر رمز دوباره فعال می‌شود.
- این تایمر فقط رابط را بازمی‌گرداند؛ قفل سرور همچنان پابرجاست و endpoint اخذ قفل اجازه پرداخت جدید نمی‌دهد.
- قفل‌های halted ناشی از نتیجه مبهم پرداخت همچنان تا بازیابی دستی متوقف می‌مانند.

## قفل مرکزی
- شناسه نصب برای هر ویندوز در `app.getPath("userData")/coordination-client.json` ساخته و ذخیره می‌شود.
- نام دستگاه از hostname ویندوز گرفته می‌شود.
- سرور فقط یک قفل سراسری نگه می‌دارد.
- قفل انقضای خودکار ندارد.
- حتی همان شناسه نصب نیز نمی‌تواند قفل باقی‌مانده را خودکار دوباره تصاحب کند.
- آزادسازی اپراتوری فقط قفل را حذف می‌کند و هیچ API پرداختی را صدا نمی‌زند.
- وضعیت و رویدادهای آزادسازی در `C:\ProgramData\CashKiosk\coordination-state.json` و `coordination-audit.jsonl` ذخیره می‌شوند.

## امنیت
- توکن ۳۲ بایتی تصادفی در `C:\ProgramData\CashKiosk\server-token` قرار می‌گیرد.
- اسکریپت پیکربندی ACL فایل را برای SYSTEM، Administrators و حساب اپراتور محدود می‌کند.
- توکن فقط در پردازش اصلی Electron و سرور Node خوانده می‌شود؛ renderer فقط متدهای محدود IPC را می‌بیند.
- SSO cookie و نشست سامان روی همان رایانه‌ای می‌ماند که Electron اجرا می‌شود.
- سرور مرکزی هیچ رمز سامان یا رمز شش رقمی دریافت نمی‌کند.

## محدودیت‌های نسخه
- نشانی سرور فعلاً `http://Jahromi-PC:5005` است و باید hostname شبکه‌ای رایانه مدیر قابل resolve باشد.
- نقش دستگاه با متغیر Machine ویندوز `CASH_KIOSK_ROLE` تعیین می‌شود؛ پس از تغییر نقش باید از Windows خارج و دوباره وارد شد.
- سرور در نقش مدیر به‌صورت child process جداشده اجرا می‌شود. راه‌اندازی و ماندگاری آن باید در آزمون واقعی reboot و خروج از برنامه تأیید شود.
- وضعیت lock در رابط کیوسک و API باید در شبکه واقعی و هنگام قطع/بازگشت ارتباط آزمایش شود.
