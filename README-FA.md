# کیوسک پرداخت صندوق — نسخه دسکتاپ ۲.۳

## وضعیت
نسخه ۲.۳ علاوه بر قابلیت‌های نسخه ۲.۲.۱، دریافت Raw Input دانگل Genius بدون نیاز به فوکوس پنجره کیوسک، پشتیبانی از چهار کلید عملیاتی NumPad و بازگشت رابط هشدار قفل قدیمی به حالت آماده پس از ۱۰ ثانیه را اضافه می‌کند. تا پایان آزمون واقعی روی هر دو رایانه، آن را برای پرداخت عملیاتی نکنید.

## پیش‌نیاز
- Windows 10 نسخه ۶۴ بیتی
- Node.js نسخه LTS برای اجرای توسعه و ساخت
- دسترسی شبکه داخلی بین دو رایانه
- باز بودن TCP پورت 5005 روی رایانه مدیر صندوق

## پیکربندی اولیه دو رایانه
اگر سرور قدیمی را دستی در PowerShell اجرا کرده‌اید، ابتدا پنجره آن را ببندید تا پورت 5005 آزاد شود. سپس فایل `scripts/configure-device.ps1` را با دسترسی Administrator اجرا کنید.

روی رایانه مدیر صندوق:
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\configure-device.ps1 -Role Server
```
اسکریپت یک توکن تصادفی ۲۵۶ بیتی تولید می‌کند، آن را در `C:\ProgramData\CashKiosk\server-token` ذخیره می‌کند و دسترسی فایل را محدود می‌کند. توکن نمایش داده و در Clipboard کپی می‌شود. آن را فقط از یک مسیر امن و محلی به رایانه اپراتور منتقل کنید.

روی رایانه اپراتور:
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\configure-device.ps1 -Role Client
```
توکن را در ورودی امن وارد کنید. فایل توکن در همان مسیر محلی ذخیره می‌شود.

پس از پیکربندی هر دو رایانه، از Windows خارج شوید و دوباره وارد شوید تا متغیر نقش دستگاه در نشست ویندوز اعمال شود. توکن را در چت، ایمیل یا GitHub قرار ندهید.

## اجرای توسعه
```powershell
npm install
npm start
```
روی رایانه مدیر، برنامه با نقش `server` ابتدا سلامت سرور مرکزی را بررسی می‌کند و در صورت نیاز سرور را در پس‌زمینه راه‌اندازی می‌کند. روی رایانه اپراتور، برنامه فقط به سرور `http://Jahromi-PC:5005` متصل می‌شود.

## ساخت نصب‌کننده
```powershell
npm install
npm run dist
```
خروجی نصب‌کننده در پوشه `dist` قرار می‌گیرد. تنظیم نقش و توکن همچنان باید طبق بخش پیکربندی اولیه انجام شود.

## قواعد ایمنی پرداخت
- هر دو کیوسک برای شروع پرداخت باید قفل انحصاری سرور مرکزی را دریافت کنند.
- پس از اخذ قفل، فهرست درخواست‌ها دوباره و مستقیم از سامان دریافت می‌شود؛ cache برای تصمیم پرداخت استفاده نمی‌شود.
- هر قفل موجود، حتی اگر متعلق به همان شناسه نصب باشد، مانع اخذ قفل جدید است. قفل قدیمی پس از راه‌اندازی مجدد خودکار تصاحب نمی‌شود.
- خطای صریح رمز اشتباه اجازه بررسی درخواست بعدی را می‌دهد؛ خطای مبهم پرداخت، قفل را در حالت توقف نگه می‌دارد.
- پس از پاسخ قطعی موفق، آزادسازی قفل انجام می‌شود. شکست آزادسازی هرگز باعث ارسال مجدد پرداخت نمی‌شود.
- بازیابی اپراتوری فقط قفل را آزاد می‌کند؛ هیچ درخواست پرداختی را ارسال یا تکرار نمی‌کند. اپراتور باید ابتدا وضعیت را در سامان بررسی کند.
- انقضای خودکار قفل غیرفعال است؛ این رفتار fail-safe است.

## چاپ
چاپ PDF به‌صورت بی‌پنجره با اندازه A6 به چاپگر پیش‌فرض Windows ارسال می‌شود. چاپگر USB یا شبکه باید ابتدا در Windows نصب و به‌عنوان چاپگر پیش‌فرض انتخاب شود. خطای چاپ باعث تکرار پرداخت نمی‌شود.

## ورودی رمز در نسخه ۲.۳
- کادر رمز از نوع متن است و ارقام واردشده را به‌صورت واقعی نمایش می‌دهد؛ مقدار رمز با نقطه یا ستاره پوشانده نمی‌شود.
- در ویندوز، برنامه یک شنونده Raw Input را در فرایند PowerShell مخفی اجرا می‌کند. این شنونده مسیر دستگاه را بررسی می‌کند و فقط دستگاه Genius با شناسه `VID_248A&PID_8367` را می‌پذیرد.
- رویدادهای `keydown` ارقام ۰ تا ۹ و کلیدهای `/`، `-`، `+` و `*` از دستگاه شناسایی‌شده به فرایند اصلی Electron ارسال می‌شوند؛ `keyup` فقط وضعیت فشردگی را آزاد می‌کند.
- برای جلوگیری از ثبت تکراری یک کلید در اثر auto-repeat، کلید تا زمان دریافت رویداد `keyup` فقط یک بار پذیرفته می‌شود.
- در دستگاه با نقش `client`، Electron رویدادهای legacy ارقام را از همه کیبوردها پیش از رسیدن به صفحه مسدود می‌کند؛ این رفتار fail-closed است و حتی در صورت جداشدن دانگل، کیبورد اصلی جایگزین نمی‌شود. در دستگاه‌های دیگر، با شناسایی دانگل همین محدودیت فعال می‌شود. ارقام دانگل فقط از مسیر Raw Input به کادر رمز می‌رسند؛ ورودی مستقیم کادر نیز `readonly` است.
- اتصال یا جداکردن دانگل در زمان اجرای برنامه پایش می‌شود. دستگاه با نقش `client` بدون دانگل ورودی عددی نمی‌پذیرد؛ دستگاه‌های دیگر مسیر عادی کیبورد را حفظ می‌کنند.
- دریافت Raw Input به فوکوس پنجره کیوسک وابسته نیست؛ تا وقتی صفحه پرداخت بارگذاری شده و renderer آمادگی دریافت را اعلام کرده باشد، ورودی دانگل دریافت می‌شود، حتی اگر برنامه دیگری در مانیتورهای دیگر فوکوس داشته باشد.
- کلیدهای عملیاتی NumPad: `/` بازگشت به صفحه آماده دریافت رمز، `-` حذف رقم آخر، `+` پاک کردن پیام و آماده‌سازی، `*` پاک کردن کامل رمز.
- این نسخه جلوی ورود ارقام یا کلیدهای NumPad به برنامه‌های دیگر در زمانی که آن برنامه‌ها در پیش‌زمینه هستند را نمی‌گیرد؛ این قابلیت عمداً خارج از محدوده است.
- اسکریپت کمکی `src/raw-numpad-helper.ps1` با Windows PowerShell داخلی ویندوز اجرا می‌شود و در بسته نصب به‌صورت resource مستقل قرار می‌گیرد؛ وابستگی npm جدیدی اضافه نشده است.

## رفتار قفل قدیمی و خطا
- پیام قفل قدیمی حداکثر ۱۰ ثانیه نمایش داده می‌شود و سپس رابط به حالت دریافت رمز برمی‌گردد؛ این فقط تغییر رابط است و قفل مرکزی را آزاد نمی‌کند.
- تا زمانی که قفل مرکزی واقعاً با مسیر آزادسازی اپراتوری و پس از بررسی سامان آزاد نشده باشد، سرور هر تلاش پرداخت را رد می‌کند.
- خطای مبهم پرداخت همچنان حالت توقف ایمن دارد و تایمر رابط نباید امکان پرداخت مجدد ایجاد کند.

## آزمون اجباری پیش از بهره‌برداری
1. سرور مرکزی روی رایانه مدیر در دسترس باشد.
2. هر دو کیوسک بتوانند وضعیت سرور را بخوانند.
3. درحالی‌که کیوسک اول قفل دارد، کیوسک دوم نتواند قفل بگیرد یا پرداخت کند.
4. پس از قفل‌گیری، فهرست تازه سامان دریافت شود.
5. رمز اشتباه هیچ پرداختی ثبت نکند و قفل آزاد شود.
6. یک پرداخت کنترل‌شده فقط یک بار ثبت شود و پس از موفقیت قفل آزاد شود.
7. قطع ارتباط در زمان ارسال پرداخت، وضعیت را نامشخص کند و قفل را حفظ کند.
8. بازیابی دستی، پس از بررسی سامان، فقط قفل را آزاد کند و پرداخت را تکرار نکند.
9. چاپ A6 روی چاپگر واقعی آزمایش شود.
