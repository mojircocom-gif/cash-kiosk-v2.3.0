# چک‌لیست آزمون پذیرش CASH KIOSK 2.3

این آزمون‌ها باید در محیط کنترل‌شده و قبل از پرداخت عملیاتی انجام شوند.

## پیکربندی و اتصال
- [ ] روی Jahromi-PC نقش Server تنظیم شده است.
- [ ] روی Baje-1 نقش Client تنظیم شده است.
- [ ] توکن دو دستگاه یکسان است و در Git یا چت ذخیره نشده است.
- [ ] بعد از logoff/logon، متغیر نقش در هر دو نشست دیده می‌شود.
- [ ] `http://Jahromi-PC:5005/health` از هر دو رایانه پاسخ می‌دهد.
- [ ] هر دو کیوسک می‌توانند lock/status را با توکن معتبر بخوانند.

## ورودی کیبورد عددی
- [ ] کادر رمز در شروع کاملاً خالی است و هیچ placeholder ندارد.
- [ ] پس از باز شدن کیوسک، کادر رمز خودکار آماده دریافت ورودی است.
- [ ] کادر رمز ارقام واقعی را نمایش می‌دهد و نقطه/ستاره نشان نمی‌دهد.
- [ ] در لاگ برنامه، شنونده Raw Input آماده و دستگاه `VID_248A&PID_8367` شناسایی‌شده گزارش می‌شود.
- [ ] ارقام Genius NumPad 1000 حتی وقتی پنجره کیوسک فوکوس ندارد و برنامه کاری در مانیتورهای ۲ و ۳ فعال است، وارد کادر رمز می‌شوند.
- [ ] کلید `/` به صفحه آماده دریافت رمز برمی‌گردد.
- [ ] کلید `-` آخرین رقم را حذف می‌کند.
- [ ] کلید `+` پیام را پاک و کیوسک را آماده می‌کند.
- [ ] کلید `*` کل رمز را پاک می‌کند.
- [ ] کلیدهای کنترلی NumPad از کیبورد اصلی در کادر رمز اثر نمی‌گذارند.
- [ ] با اتصال دانگل، ارقام کیبورد اصلی در کادر رمز کیوسک اثر نمی‌گذارند.
- [ ] رویدادهای کلید از سایر کیبوردها به‌عنوان ورودی NumPad پذیرفته نمی‌شوند.
- [ ] هر کلید فشرده‌شده فقط یک رقم ثبت می‌کند؛ رویداد `keyup` رقم اضافه نمی‌کند و auto-repeat باعث ثبت تکراری نمی‌شود.
- [ ] با جداکردن دانگل در زمان اجرای برنامه، وضعیت شناسایی به‌روز می‌شود؛ پس از اتصال مجدد، ورودی اختصاصی دوباره فعال می‌شود.
- [ ] روی دستگاه با نقش `client`، جداکردن دانگل باعث فعال‌شدن کیبورد اصلی به‌عنوان جایگزین نمی‌شود (رفتار fail-closed).
- [ ] در زمان ورود رمز، برنامه‌های دیگر در پیش‌زمینه آزمایش شوند؛ این نسخه تضمین نمی‌کند NumPad در آن برنامه‌ها بی‌اثر باشد.
- [ ] با ورود رقم ششم، فقط یک دور بررسی رمز شروع می‌شود.
- [ ] زمان پاسخ تک‌تک درخواست‌ها و زمان کل اسکن در Console ثبت می‌شود.
- [ ] کلیدهای کیبورد اصلی و عملکرد سایر برنامه‌ها پس از خروج از کیوسک مختل نمی‌شوند.

## رابط قفل قدیمی
- [ ] پیام قفل قدیمی پس از ۱۰ ثانیه از صفحه پاک می‌شود و کادر رمز دوباره آماده دریافت می‌شود.
- [ ] پس از پاک شدن پیام، قفل مرکزی همچنان فعال است و هیچ پرداختی بدون آزادسازی واقعی قفل انجام نمی‌شود.
- [ ] آزادسازی دستی فقط پس از بررسی درخواست و گردش صندوق در سامان انجام می‌شود و هیچ API پرداختی فراخوانی نمی‌کند.
- [ ] خطای مبهم پرداخت همچنان ورودی را متوقف می‌کند و با تایمر ۱۰ ثانیه‌ای قابل دور زدن نیست.

## انحصار پرداخت

- [ ] کیوسک B در زمان قفل A، پاسخ 409 می‌گیرد و پرداخت نمی‌کند.
- [ ] بستن برنامه A باعث آزادسازی خودکار قفل نمی‌شود.
- [ ] اجرای مجدد A همان قفل قدیمی را تصاحب نمی‌کند.
- [ ] بازیابی دستی پس از بررسی سامان، فقط قفل را آزاد می‌کند.

## منطق پرداخت
- [ ] پس از اخذ قفل، درخواست تازه از سامان دریافت می‌شود.
- [ ] اگر دریافت فهرست تازه ناموفق باشد، هیچ پرداختی ارسال نمی‌شود و قفل آزاد می‌شود.
- [ ] فهرست خالی، بدون ارسال پرداخت، قفل را آزاد می‌کند.
- [ ] رمز اشتباه صریح، درخواست بعدی را بررسی می‌کند.
- [ ] پس از اولین پرداخت موفق، حلقه پرداخت متوقف می‌شود.
- [ ] خطای مبهم باعث halt و حفظ قفل می‌شود.
- [ ] قطع ارتباط بعد از ارسال درخواست پرداخت، باعث ارسال مجدد خودکار نمی‌شود.
- [ ] اگر پرداخت موفق باشد ولی آزادسازی قفل شکست بخورد، گزینه «پرداخت انجام نشده» نمایش داده نمی‌شود.
